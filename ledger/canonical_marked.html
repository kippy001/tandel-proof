How verification works

the integrity layer

Every call on this page was timestamped at issue and is independently verifiable — you don't have to trust the record, you can check it. Each U-VCT run emits a deterministic output block; we hash it, commit the archived analysis to the public repository at issue time, and publish the resulting Run ID here. The commit timestamp is third-party proof the call existed before its outcome was known.

RUN-20260527-NVDA-c4e1a8b9
date in YYYYMMDD · hash₈ = first 8 hex of the SHA-256 over the run's canonical TOON output
  1. Hash the run. SHA-256 is computed over the canonical TOON block the engine emits — same inputs and code always produce the same 64-character digest, so anyone can recompute it from the archived file.
  2. Archive & commit. The full run is written to archive/runs/<Run ID>.toon and pushed to the repo at issue time. Git's commit timestamp anchors when.
  3. Publish the Run ID. It appears in that week's issue and in the row below. Click any Run ID here to expand its verification panel.
  4. Verify, then score. Recompute the hash from the archived TOON; confirm the pinning commit predates the close date. Only then is the trade marked W / L / Avoided.

Scoring rules

no moving goalposts

What's a win. The structure reached its stated profit target, or expired at max profit, before any stop or time-stop triggered. Outcome is fixed at the published management plan — no retroactive redefinition.

What's a loss. The stop or short-strike rule triggered, or the position closed below break-even at the time stop. Losses appear in the same ledger as wins, with the same prominence.

"Avoided" is not a win. A correctly-flagged NO_TRADE (e.g. TSLA into earnings) is logged as Avoided and excluded from the W/L hit-rate. It's recorded because skipping a bad trade is a real outcome of the process — but it doesn't pad the record.

Net edge captured. Sum of realized P/L across closed positions on a normalized 1-contract basis. It is an illustrative tracking figure, not a live-account return, and assumes modeled fills.

One entry per run. Each row maps to exactly one archived Run ID. Re-issues after a mid-cycle OVERRIDE get their own Run ID and their own row; the superseded run is retained, not deleted.

Nothing leaves the ledger. Once published, a row is permanent. Corrections are appended and dated, never overwritten.
